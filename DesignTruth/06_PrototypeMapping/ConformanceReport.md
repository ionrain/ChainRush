## Detailed Conformance

---

### 1) Grid Generation

**Spec:**  
`design_truth/02_systems/grid_generation_rules.md`

**Implementation:**  
`BoardUi.cs`, `CellUi.cs`

#### Confirmed Matches
- Availability-first generation (cooldown ≥ interval).
- Per-type cooldown accumulation over time.
- Progress-driven interval curves via LevelDifficultyData.
- Guaranteed fractions via `alwaysAvailableOnRefresh`.
- Grid is regenerated fully per refresh.
- Cooldowns reset for used types only.

#### Partial / Notes
- Pattern shapes are implemented as `CellSelectPatternType`,
  but spec treats patterns abstractly (OK).
- Safety override (force meaningful) exists implicitly via guarantees,
  but explicit danger override logic is not yet implemented.

**Decision:**  
Spec reflects current behavior accurately.  
Future danger overrides should be added on top, not replace logic.

**Status:** MATCH

---

### 2) Grid Availability & Refresh Economy

**Spec:**  
`design_truth/02_systems/grid_refresh_economy.md`

**Implementation:**  
`BoardUi.cs`, `LevelDifficultyData.cs`

#### Confirmed Matches
- Refresh pacing controlled by cooldown intervals, not RNG.
- Intervals evaluated via curves based on normalized progress.
- Meaningful vs Filler behavior is implicitly controlled by:
  - interval lengths
  - guaranteed fractions

#### Divergences
- RefreshType (Meaningful/Filler) is not explicit in code;
  instead, behavior emerges from interval configuration.

**Decision:**  
Spec explicitly names the model that already exists implicitly.
No contradiction.

**Status:** MATCH

### 3) Tile Pools & Categories
